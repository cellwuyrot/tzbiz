# Первичный аудит TRIOZ Business (до изменений)

Источник: предоставленный tzbiz-main.zip. Production, реальные SMTP и основная платформа не доступны и не изменялись.

## Архитектура
Next.js 15 App Router / React 19 / TypeScript / Tailwind; Prisma 6; PostgreSQL production, SQLite development. scripts/prisma-sync.mjs выбирает схему и миграции по DATABASE_URL, production требует PostgreSQL. История: 0001_init → 0002_content → 0003_leads. Модели: User, Session, Project, Service, ServiceMedia, SiteSettings, LeadRequest. Подписок и платежей нет.

Публичная заявка: Origin → in-memory rate limit 4/15 минут → JSON/Zod → honeypot → опубликованная Service → создание LeadRequest с privacyConsentAt → одно внутреннее SMTP-письмо → 201 {ok,emailNotified}. Клиентская форма не использует emailNotified и подтверждает только обращение. SMTP-ошибка не удаляет запись, но выводится целиком через console.error.

Аккаунты создаются администратором; bcrypt, HMAC-хеш токена сессии в БД; cookie HttpOnly/SameSite=Lax/Secure production, 7 дней. Серверные страницы проверяют роль; каждый admin API проверяет ADMIN; изменяющие методы проверяют double-submit CSRF. Сброс пароля транзакционно отзывает сессии. Клиент получает только назначенные проекты; файловая выдача проверяет публикацию/роль/владельца. Middleware только устанавливает noindex, не заменяет авторизацию.

/connect — внешняя навигационная ссылка со slug услуги. Это не аутентификация, не API, не создание платёжной сессии. Локальное сопоставление заявки по email в админке не является связыванием аккаунтов основной платформы.

## Риски и план
1. Нет клиентского письма, независимых статусов и тестов mailer → расширить тот же Nodemailer, allSettled, текст/HTML, безопасные логи.
2. SMTP-логин нельзя выводить из sender; разрешение union@business.trioz.ru неизвестно → только конфигурационный контракт, без вымышленных реквизитов.
3. Нет публичных документов и отдельного принятия соглашения → /agreement, /privacy, два чекбокса, серверные версии/дата, nullable добавления в обе схемы и миграции без фиктивного согласия старых заявок.
4. SEO жёстко указывает trioz.ru → отдельная базовая URL-конфигурация Business, сохранить внешние ссылки connect.
5. Rate limit в памяти не общий между процессами, expired ключи не очищаются; доверие X-Forwarded-For зависит от reverse proxy. Origin отсутствует — публичный API допускает запрос; CSRF-токен на нём не применяется. Это антиспам, не гарантия от ботов. Изменение proxy/лимитов вне объёма.
6. Ошибки service/find/create не превращены в безопасный JSON → добавить узкий generic 500 без содержимого ошибок; админские catch-all могут маскировать ошибки БД как 404/успешное удаление. Админские исправления отдельным этапом, архитектуру не менять.
7. SMTP без durable retry; сбой/остановка процесса между commit и отправкой теряет уведомление, не заявку → не обещать доставку; описать минимальный outbox только при требовании гарантии.
8. Нет юрнаименования, реквизитов оператора и утверждённых сроков хранения → явно предварительные документы и список подтверждений до production.
9. Нет исходников/API основной платформы и подтверждённого платёжного сценария → предложенный контракт, не выдавать его за найденный API.

Первичная проверка: npm ci успешно; исходные 7 файлов / 17 тестов прошли. Другие исходные проверки не проводились отдельно до изменений.
