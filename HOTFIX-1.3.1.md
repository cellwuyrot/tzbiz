# Исправление 1.3.1: Ubuntu 22.04, QEMU CPU без SSE4.2

## Причина

В версии 1.3.0 обработчик uploads импортировал native `sharp` на уровне модуля. На данном VPS виртуальный CPU `QEMU Virtual CPU version 2.5+` не предоставляет SSE4.2/x86-64-v2. Native sharp не загружался; Wasm fallback тоже не работал из-за отсутствия Wasm SIMD. Поэтому импорт некоторых API-обработчиков падал ещё до проверки доступа.

Отдельная проблема — установленный Node 20.20.2, тогда как проект/Vitest 5 требуют Node >=22.12. На сервере работают ещё пять PM2-приложений, поэтому системные Node/PM2 и конфигурацию виртуального CPU это исправление не меняет.

## Изменения

- Удалён прямой импорт и использование sharp в обработчиках загрузки и тестах.
- PNG/JPEG/WebP проходят проверку размеров, полное декодирование, auto-orient и удаление метаданных через системный ImageMagick. Допускается только явно заданный растровый декодер; имя загруженного файла не передаётся в команду.
- Процессы запускаются без shell, с ограничениями ресурсов и таймаутом. В `config/imagemagick/policy.xml` запрещены delegates, фильтры и прочие кодеры.
- Нет бесконтрольного fallback, который сохраняет повреждённые файлы без проверки.
- Добавлена `npm run images:check` и проверка процессора изображений в `launch:check`.
- Встроенный Next image optimizer отключён (`images.unoptimized=true`). Компоненты проекта уже использовали обычные изображения/MediaImage. Sharp может оставаться optional-зависимостью самого Next в node_modules, но приложение не загружает его для своих uploads и не использует native-оптимизацию изображений.
- Добавлен отдельный установщик Node 22: `scripts/install-node22-isolated.sh`.
- Новых миграций нет; применённая `20261028140000_tbank_checkout` не менялась. БД сбрасывать/пересоздавать нельзя.

## Установка на сервере пользователя

Сначала загрузите файлы версии 1.3.1 в свой Git-репозиторий. Ниже команды выполняются **по порядку и в одной SSH-сессии**, остановитесь при любой ошибке.

### 1. Обновить код

```bash
cd /var/www/tzbiz
git pull --ff-only
```

Если pull сообщает конфликт, не применяйте reset/clean: сохраните вывод и разберите конфликт отдельно.

### 2. Установить системный обработчик изображений

Для Ubuntu 22.04:

```bash
apt-get update && apt-get install -y imagemagick ca-certificates curl xz-utils
```

Это не `apt upgrade` и не обновление системного Node/PM2. Не запускайте reboot или restart всех PM2-процессов.

### 3. Поставить отдельный Node 22 только для tzbiz

```bash
bash scripts/install-node22-isolated.sh
```

Установщик загружает официальный Linux x64 tarball из `https://nodejs.org/dist/latest-v22.x/`, проверяет SHA-256 по официальному манифесту и проверяет запуск бинарника до переключения ссылки. Манифест и архив получаются по HTTPS; это проверка контрольной суммы, а не отдельная PGP-проверка релиза.

Он устанавливает версионный каталог в `/opt/tzbiz-node22/` и ссылку `/opt/tzbiz-node22/current`. `/usr/bin/node`, `/usr/bin/npm`, системный PM2 и запущенные процессы не меняются. Если бинарник Node не запускается на CPU сервера, установщик остановится: не продолжайте развёртывание.

Затем только в текущем терминале:

```bash
export PATH="/opt/tzbiz-node22/current/bin:$PATH"
hash -r
node -v
npm -v
```

`node -v` должен вывести `v22.x` (не ниже 22.12).

### 4. Зависимости, проверка изображений, тесты и сборка

```bash
npm ci && npm run db:generate && npm run images:check && npm test && npm run build
```

Не добавляйте `--omit=optional`: это также удалит optional SWC-бинарники Next. Для этого hotfix новых миграций нет; предыдущая миграция у пользователя уже успешно применена. Рабочий `.env`, uploads и БД сохраняются.

Если `images:check` или тесты не прошли, PM2 не перезапускайте. Декодеры JPEG/PNG/WebP проверяются тестами реальными маленькими файлами, а не только командой `convert -version`.

### 5. Перезапустить только tzbiz с отдельным Node

В той же SSH-сессии с изменённым PATH:

```bash
/usr/bin/pm2 restart tzbiz --interpreter /opt/tzbiz-node22/current/bin/node --update-env
/usr/bin/pm2 save
/usr/bin/pm2 show tzbiz
/usr/bin/pm2 logs tzbiz --lines 60
```

Перезапускать следует **только tzbiz**. Не выполняйте `pm2 update`, `pm2 kill`, `pm2 restart all` и не переустанавливайте PM2 глобально: они могут затронуть другие сайты. В выводе `pm2 show tzbiz` проверьте новый interpreter; online сам по себе не подтверждает работу входа/оплаты — проверьте сайт и загрузку изображения.

Если задание обслуживания запускается отдельным systemd/cron, настройте для **его** команд тот же PATH Node 22. Пример для systemd unit tzbiz (реальное имя unit проверьте на сервере):

```ini
Environment="PATH=/opt/tzbiz-node22/current/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
```

Это не требуется применять к systemd unit самого общего PM2-демона.

## Проверки исправления

- Контрольный прогон под отдельным официальным Node 22.23.4.
- Полный набор Vitest: 33 файла, 313 тестов. Приложение не использует sharp/Wasm для обработки загрузок.
- Проверены реальные PNG, JPEG, WebP, повреждённые изображения, маскировка SVG, отсутствие convert/identify и сохранение API guard-проверок без native sharp.
- TypeScript, ESLint и production-сборка Next.js.
- Установщик проверен в отдельном каталоге; системный Node не изменялся.

Проверки выполнены в локальном окружении, а не на VPS пользователя: точный старый QEMU CPU и Ubuntu-пакеты здесь не эмулировались. Поэтому на сервере обязательны images:check, полный npm test и build до перезапуска. Для установленного ImageMagick поддерживайте актуальные security-обновления Ubuntu.

Настройки TZ ID, банковского терминала, фискализации, перенос старых аккаунтов и порядок резервного копирования из RELEASE-1.3.0.md остаются в силе. Это исправление не включает реальную оплату без настройки терминала и не добавляет автоматическую выдачу внешних подписок.
